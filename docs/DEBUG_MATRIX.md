## P2: 今後E2E化する候補

- 初回起動 → 料理選択 → 抽選 → 決定 → 履歴確認
- みんなで → 店を決める → 2店舗追加 → 抽選 → 保存
- 保存済み → 再抽選
- 道中で探す → 条件入力 → 店舗検索 → 候補から抽選
- リロード後の保存/履歴復元
- API失敗後の再試行

## 判定

- **PASS**: 仕様どおりで再現性あり
- **FAIL**: 仕様と異なる
- **BLOCKED**: 外部依存などで確認不能
- **NOT TESTED**: 未確認

Critical / High の FAIL が残っている状態ではデバッグ完了にしない。

### 修正記録

- **Medium — 条件変更後に古い道中検索結果が表示される**。再現手順: 道中検索を開始し応答を保留 → 条件を変更 → 古い候補応答を返す。期待結果は旧条件の候補を破棄。原因は検索完了時に開始時条件との整合性を確認していなかったこと。検索要求IDで無効化し、現行要求の応答だけを反映するよう修正。回帰テストはPASS。
- **Medium — 不正なAPI成功レスポンスを候補として通す**。再現データ: 不正JSON、`{}`、`{"candidates":[null]}`。原因はHTTP 200後にJSON shapeを検証せず、候補配列の有無だけで判定していたこと。必須候補フィールドとレスポンスshapeを検証し、無効な応答を既存の取得失敗処理へ渡す。回帰テストはPASS。

### 外部依存・残件

- 公開SiteでGoogle Routes / Places APIへの実リクエストが成功した。一時診断ではPlacesの1ページ目に20件があり、`nextPageToken` も返った。はま寿司は1ページ目に含まれていたため、この回の不掲載はページネーションが原因ではない。
- はま寿司はAPI応答時に `openNow:false`。出発地→店舗は約12分、通常ルートとの差は約11分で、上限10分を超過した。今回の夜間検索での直接の除外理由は営業時間条件と寄り道上限。営業時間内なら営業時間条件は通るが、同じ経路時間なら上限超過で除外される。
- Googleマップで当該店を経由地に指定した現時点の画面は約39分を表示し、Routes APIの通常ルート約26分55秒に対して差が10分を超える方向で整合。ただし交通状況とAPIの経路選択が異なるため、別時刻での同じ数値は保証しない。
- 利用者が報告した営業時間内の回のAPI応答・時刻・正確な条件は保存されておらず、その回を再現できていない。したがって報告された回の直接原因は未確定。今回のデータでは「寿司」検索や候補取得漏れではなく、寄り道上限による除外が主因候補。
- 原因候補をコード上で分解した。通常の料理・場所検索はGoogle Mapsへの検索URLを作り、公開アプリ内でPlaces候補取得はしない。一方、道中検索はRoutes APIが返した1本目のポリラインと道中検索語「寿司」をPlaces Text Searchへ渡す。ユーザーがGoogle Mapsで行う地点周辺検索とアプリのPlaces Search Along Routeは別の検索経路であり、候補集合は同一ではない。Providerの非route分岐も別途あり、座標がある場合は5km `locationBias` を使う。
- Placesの道中検索は最大20件/ページで、アプリは1ページだけ読む。今回 `nextPageToken` は存在したが、はま寿司は1ページ目にいたため、この回に限りページ未取得は原因でない。別の時間・ルートで上位20件に入らない可能性までは否定できない。
- 1ページ目で得た候補は、`eatingTime === 'now'` の場合 `currentOpeningHours.openNow === true` のみ残す。出発地→店舗の「移動時間」上限と、routing summaryの2 legs合計から通常ルート時間を引いた寄り道上限も適用する。今回、はま寿司は `openNow:false`、店舗まで約12分、寄り道約11分で、10分上限では不採用が仕様どおり。
- 診断用の一時ログ機能はローカルソースから除去し、本番環境変数も解除した。診断コードを含まないソース版の本番公開は自動審査で拒否されたため未反映。ローカルに残した公開前ソースには診断コードはなく、未公開ソースの保持先はSites checkout。
- Google Mapsの外部サイトを開いた先の検索結果は確認していない。生成URLの値のみ確認。
- 物理モバイル端末、モバイルviewport、ソフトキーボードの表示は未確認。
- 通信が永久に応答しないケースは未確認。遅延して応答した場合の競合は確認済み。
